# creator.dm

TikTok Shop のクリエイターへ複数アカウントから DM を送付する運用を、一元管理するための社内ツールです。

- 運用者 10 名 × 1 人あたり 5 アカウント程度の運用を想定
- 日次の送付数・返信数を運用者が手入力し、そこから報酬・アラート・転換率を自動で算出します

## 画面はDM送付者用と管理者用で完全に分かれています

ログインすると役割に応じた画面に振り分けられます。DM送付者が管理画面のURLを直接開いても
自分の入力画面に戻されるため、他の人の実績や報酬設定が見えることはありません。

### DM送付者の画面（`/my`）

毎日の入力に集中できるよう、サイドバーのない4タブ構成にしています。

| タブ | 内容 |
| --- | --- |
| 今日の入力 | 自分のアカウントごとに送付数・返信数・メモを入力。入力しながら合計・返信率がその場で更新され、返信数が送付数を超えていると保存できません。下に直近7日の入力状況が並び、未入力の日は赤く表示され、そのままタップして遡って入力できます |
| 自分の実績 | 自分の送付数・返信率・30日推移・ファネル・アカウント別の内訳・月別の実績と報酬見込み |
| LINE・面談 | 返信があったクリエイターを登録し、LINE登録 → 面談 → 成約 とステージを進める |
| 送付文章 | 自分の文面の確認とコピー、編集（保存すると新しい版になり、前の版に戻せます） |

### 管理者の画面

| 機能 | 画面 | 内容 |
| --- | --- | --- |
| 全体管理 | ダッシュボード | 全運用者の送付数・返信率・報酬見込みを1画面で俯瞰。日次推移とファネルも表示 |
| アラート | アラート | 返信率の低下、日報の未入力、送付ゼロのアカウント、LINE転換率の低下などを自動検知 |
| 月間報酬管理 | 報酬管理 | 運用者ごとに異なる単価で自動計算。確定／支払済のステータス管理と、賞与・控除の調整に対応 |
| リード管理 | リード管理 | 全運用者のリードを横断で確認・修正 |
| 送付文章の管理 | 送付文章 | 全運用者の文面を確認・編集。変更履歴も参照できます |
| アカウント管理 | アカウント | TikTokアカウントの登録、稼働／停止／BANの管理、送付目標の設定 |
| 代理入力 | 日報の代理入力 | 送付者が入力できないときに、管理者が代わりに登録・修正する |
| メンバー・単価 | メンバー・単価 | 運用者の登録と、送付単価・ボーナス・月額固定の設定 |

### 権限

| | DM送付者 | 管理者 |
| --- | --- | --- |
| 自分の日報・文章・リード | ○ | ○ |
| 他の人のデータ | × | ○ |
| 報酬管理・単価設定・メンバー管理・アラート設定 | × | ○ |

## 技術構成

- Next.js 16（App Router / Server Actions）+ React 19 + TypeScript
- SQLite（better-sqlite3）— 外部DBサーバー不要。データは `data/creator-dm.db` の1ファイル
- 認証は HMAC 署名付き Cookie ＋ scrypt によるパスワードハッシュ（追加ライブラリなし）
- グラフは依存パッケージを使わず素の SVG で描画

## セットアップ

```bash
npm install
cp .env.example .env          # APP_SECRET を必ず変更してください
npm run seed                  # 初期管理者を作成（admin / admin1234）
npm run dev                   # http://localhost:3000
```

動作イメージを掴みたい場合は、デモデータ（運用者10名 × 5アカウント × 約60日分）を投入できます。

```bash
npm run seed:demo             # 運用者 op01〜op10 / パスワード password1234
```

### 本番起動

```bash
npm run build
npm start
```

`next start` はプロジェクトルートから実行してください（起動時に `src/lib/schema.sql` を読み込みます）。

## 環境変数

| 変数 | 用途 |
| --- | --- |
| `APP_SECRET` | セッションCookieの署名鍵。本番では必ず長いランダム文字列に変更してください（未設定だと本番起動時にエラーになります） |
| `DATABASE_PATH` | SQLite ファイルの保存先。省略時は `./data/creator-dm.db` |
| `SEED_ADMIN_LOGIN_ID` / `SEED_ADMIN_PASSWORD` | seed 実行時の初期管理者。既にユーザーがいる場合は無視されます |

`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` で `APP_SECRET` を生成できます。

## 運用のながれ

1. 管理者が **メンバー・単価** で送付者を登録し、DM単価・ボーナス・月額固定を設定する
2. 管理者が **アカウント** に TikTok アカウントを登録する（1日の送付目標も設定可）
3. 送付者が毎日 **今日の入力**（`/my`）で送付数・返信数を入力する
4. 送付者が返信のあったクリエイターを **LINE・面談** に登録し、面談・成約まで進める
5. 管理者が **アラート** で返信率の悪化や入力漏れを確認し、必要なら **送付文章** を見直す
6. 月末に **報酬管理** で金額を確認し、確定 → 支払済 にする

### 単価の考え方

報酬は次の式で計算されます。

```
送付数 × DM単価
  + 返信数   × 返信単価
  + LINE登録数 × LINEボーナス
  + 面談実施数 × 面談ボーナス
  + 月額固定
  + 調整（賞与・控除など）
```

単価は「適用開始月」つきで登録されるため、単価を変更しても過去の月の金額は変わりません。
使わない項目は 0 のままにしておけば計算に影響しません。

### アラートの閾値

**アラート設定** から変更できます。初期値は次のとおりです。

| 項目 | 初期値 |
| --- | --- |
| 判定対象期間 | 直近 7 日 |
| 判定に必要な最低送付数 | 50 件 |
| 返信率の注意ライン / 危険ライン | 8% / 5% |
| 日報未入力の警告日数 | 2 日 |
| LINE転換率の注意ライン | 20% |

送付数が「最低送付数」に満たない期間は、母数が小さく率が安定しないため返信率の判定をスキップします。

## バックアップ

データは SQLite の1ファイルにまとまっています。定期的に次をコピーしてください。

```bash
cp data/creator-dm.db backup/creator-dm-$(date +%Y%m%d).db
```

## 補足

- 日付は常に日本時間（JST）基準で判定します。
- DM の送付数・返信数は運用者による手入力です。TikTok からの自動取得は行いません。
