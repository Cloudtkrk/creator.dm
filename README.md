# creator.dm

TikTok Shop のクリエイターへ複数アカウントから DM を送付する運用を、一元管理するための社内ツールです。

- 運用者 10 名 × 1 人あたり 5 アカウント程度の運用を想定
- 日次の送付数・返信数を運用者が手入力し、そこから報酬・アラート・転換率を自動で算出します

## 画面はDM送付者用と管理者用で完全に分かれています

ログインすると役割に応じた画面に振り分けられます。DM送付者が管理画面のURLを直接開いても
自分の入力画面に戻されるため、他の人の実績や報酬設定が見えることはありません。

### DM送付者の画面（`/my`）

毎日の入力に集中できるよう、サイドバーのない4タブ構成にしています。

| タブ | 内容 |
| --- | --- |
| 今日の入力 | 自分のアカウントごとに送付数・返信数・メモを入力。入力しながら合計・返信率がその場で更新され、返信数が送付数を超えていると保存できません。下に直近7日の入力状況が並び、未入力の日は赤く表示され、そのままタップして遡って入力できます |
| 自分の実績 | 自分の送付数・返信率・30日推移・ファネル・アカウント別の内訳・月別の実績と報酬見込み |
| LINE誘導 | 返信があったクリエイターを登録し、LINEに誘導できたら日付を入れる。入力するのは**クリエイターID・送付アカウント・返信日・LINE誘導日の4項目だけ**。面談・成約は管理者が記録するため、ここでは参照のみ |
| 送付文章 | 自分の文面の確認とコピー、編集（保存すると新しい版になり、前の版に戻せます） |

### 管理者の画面

| 機能 | 画面 | 内容 |
| --- | --- | --- |
| 全体管理 | ダッシュボード | 全運用者の送付数・返信率・報酬見込みを1画面で俯瞰。日次推移とファネルも表示 |
| アラート | アラート | 返信率の低下、日報の未入力、送付ゼロのアカウント、LINE転換率の低下などを自動検知 |
| 月間報酬管理 | 報酬管理 | 運用者ごとに異なる単価で自動計算。確定／支払済のステータス管理と、賞与・控除の調整に対応 |
| リード管理 | リード管理 | 全運用者のリードを横断で確認・修正。**面談実施と成約の記録はここで行う**（有無のチェック＋日付、または一覧のボタンでワンクリック） |
| 送付文章の管理 | 送付文章 | 全運用者の文面を確認・編集。変更履歴も参照できます |
| アカウント管理 | アカウント | TikTokアカウントの登録、稼働／停止／BANの管理、送付目標の設定 |
| 代理入力 | 日報の代理入力 | 送付者が入力できないときに、管理者が代わりに登録・修正する |
| メンバー・単価 | メンバー・単価 | 運用者の登録と、送付単価・ボーナス・月額固定の設定 |

### 権限

| | DM送付者 | 管理者 |
| --- | --- | --- |
| 自分の日報・文章・リード | ○ | ○ |
| 他の人のデータ | × | ○ |
| 報酬管理・単価設定・メンバー管理・アラート設定 | × | ○ |

## 技術構成

- Next.js 16（App Router / Server Actions）+ React 19 + TypeScript
- PostgreSQL（`pg`）— Vercel の Storage から接続した Postgres をそのまま使えます
- 認証は HMAC 署名付き Cookie ＋ scrypt によるパスワードハッシュ（追加ライブラリなし）
- グラフは依存パッケージを使わず素の SVG で描画

テーブルはアプリの初回アクセス時に自動作成されます（`CREATE TABLE IF NOT EXISTS` を
アドバイザリロックで直列化しているため、複数のインスタンスが同時に起動しても安全です）。
マイグレーションコマンドを実行する必要はありません。

## Vercel へのデプロイ

1. Vercel で **Add New → Project** から、このリポジトリを Import する
2. **Storage → Create Database → Postgres（Neon）** を作成し、このプロジェクトに Connect する
   - `DATABASE_URL` などの環境変数が自動で追加されます
3. **Settings → Environment Variables** に `APP_SECRET` を追加する（Production / Preview / Development すべてにチェック）
   - 値は次のコマンドで生成できます
     ```bash
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
     ```
4. **Deployments → Redeploy**（3で環境変数を足したあとに再デプロイが必要です）
5. 公開された URL を開くと初回セットアップ画面が出るので、管理者アカウントを作成する

以降は管理者でログインし、**メンバー・単価** から送付者を登録して運用を開始します。
`APP_SECRET` を後から変更すると、全員がログアウトされます（作り直す場合以外は変更しないでください）。

### デモデータを本番に入れたい場合（任意）

Vercel の Postgres の接続文字列をローカルの `.env` に書いてから実行します。運用開始前だけにしてください。

```bash
npm run seed:demo
```

## ローカルで動かす

```bash
npm install
cp .env.example .env    # DATABASE_URL と APP_SECRET を設定
npm run dev             # http://localhost:3000
```

`DATABASE_URL` には Vercel の開発用ブランチの接続文字列か、手元の PostgreSQL を指定します。
デモデータ（運用者10名 × 5アカウント × 約60日分）を入れる場合：

```bash
npm run seed:demo       # 運用者 op01〜op10 / パスワード password1234
```

## 環境変数

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL の接続文字列。Vercel で Postgres を Connect すると自動で入ります（`POSTGRES_URL` でも可） |
| `APP_SECRET` | セッションCookieの署名鍵。**必須**。本番で未設定だとエラーになります |
| `SEED_ADMIN_LOGIN_ID` / `SEED_ADMIN_PASSWORD` | `npm run seed` で作る初期管理者。画面からセットアップする場合は不要です |
| `DB_POOL_MAX` | 接続プールの上限（既定 3）。通常は変更不要です |

## 運用のながれ

1. 管理者が **メンバー・単価** で送付者を登録し、DM単価・ボーナス・月額固定を設定する
2. 管理者が **アカウント** に TikTok アカウントを登録する（1日の送付目標も設定可）
3. 送付者が毎日 **今日の入力**（`/my`）で送付数・返信数を入力する
4. 送付者が返信のあったクリエイターを **LINE誘導** に登録し、LINEに誘導できたら日付を入れる
5. 管理者が **リード管理** で面談の実施と成約を記録する
6. 管理者が **アラート** で返信率の悪化や入力漏れを確認し、必要なら **送付文章** を見直す
7. 月末に **報酬管理** で金額を確認し、確定 → 支払済 にする

### 単価の考え方

報酬は次の式で計算されます。

```
送付数 × DM単価
  + 返信数   × 返信単価
  + LINE登録数 × LINEボーナス
  + 面談実施数 × 面談ボーナス
  + 月額固定
  + 調整（賞与・控除など）
```

単価は「適用開始月」つきで登録されるため、単価を変更しても過去の月の金額は変わりません。
使わない項目は 0 のままにしておけば計算に影響しません。

### アラートの閾値

**アラート設定** から変更できます。初期値は次のとおりです。

| 項目 | 初期値 |
| --- | --- |
| 判定対象期間 | 直近 7 日 |
| 判定に必要な最低送付数 | 50 件 |
| 返信率の注意ライン / 危険ライン | 8% / 5% |
| 日報未入力の警告日数 | 2 日 |
| LINE転換率の注意ライン | 20% |

送付数が「最低送付数」に満たない期間は、母数が小さく率が安定しないため返信率の判定をスキップします。

## バックアップ

Vercel の Postgres（Neon）は自動でバックアップされますが、手元に控えを取る場合は次のようにします。

```bash
pg_dump "$DATABASE_URL" > backup/creator-dm-$(date +%Y%m%d).sql
```

## 補足

- 日付は常に日本時間（JST）基準で判定します。
- DM の送付数・返信数は運用者による手入力です。TikTok からの自動取得は行いません。
